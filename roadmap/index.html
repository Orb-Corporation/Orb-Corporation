PROGRAMMING LANGUAGE

Orb!

0.3.0 · On main

Orb! is evolving from a Linux-focused native systems language toward a compiler with additional platform targets and better developer tooling.

Current main version: 0.3.0 (merged 14 November 2026). Official release publication is still pending.

  • Linux x86-64: fully supported and tested.
  • Windows via WSL2: recommended Windows workflow, using the Linux compiler in WSL2.
  • Native Windows x86-64 and macOS x86-64: experimental targets, not yet executed on real Windows/macOS hardware.
  • VS Code support includes syntax highlighting, snippets, completions, hover documentation, signature help, run/build/check commands, diagnostics, tasks and WSL integration.
  • The orb pkg package manager installs and verifies source-only modules from public GitHub repositories using a lockfile.
  • The standard library includes JSON validation and string quoting, alongside the existing core, math, strings, I/O and vector modules.
  • orb doctor, improved module-member typo suggestions and --target linux|macos|windows improve toolchain diagnosis and target selection.

DELIVERED LANGUAGE CAPABILITY

Web Development Library

Implemented

Orb! now includes a first-party browser integration library for WebAssembly applications. It lets Orb! code work with browser APIs while HTML and CSS remain the page structure and styling standards.

Delivered: 14 November 2026 · included in the 0.3.0 code line.

  • DOM lookup and manipulation, element properties, attributes, classes and styles.
  • Browser events, callbacks, timers and console output.
  • Local/session storage, URL and location access, and asynchronous browser fetch.
  • JSON parsing, construction and serialisation through the browser integration runtime.

NEXT LONG-TERM LANGUAGE GOAL

Performance and efficiency.

Long term

Improve the compiler's optimiser, code generation and runtime efficiency, with the ambition of outperforming C++ on clearly defined, reproducible workloads.

Estimated target: during 2027.

This remains an ambition, not a current performance claim. Results will require repeatable comparisons under fair compiler settings.
