LOCAL-NETWORK DISTRIBUTED COMPUTING

TASH.

A consent-based Master/Worker application that lets devices on the same local network contribute to predefined computation tasks.

View source on GitHub ↗

Project status: experimental. Estimated target: December 2026. This date is provisional and may change.

HOW IT WORKS

One Master.
Several Workers.

The Master divides a workload into independent chunks and assigns them to Worker applications running on devices in the same local network. Workers connect to the Master and must be explicitly authorized before they participate.

The current built-in workload is a CPU benchmark that evaluates a predefined function over a range of values. It is not a general-purpose platform for sending arbitrary code to remote machines.

CURRENT CAPABILITIES

Built around
explicit consent.

Manual authorization

A pairing code and an explicit approval step are required before a Worker joins.

Predefined tasks only

Workers execute registered task types; the documented design does not execute arbitrary network-supplied code.

Windows & Linux

The current Python/Tkinter applications target Windows and Linux desktop environments.

Pause and cancel

Workers can pause or disconnect, and the Master can cancel an active computation.

Benchmarking

The application compares local execution with distributed execution; network overhead can make small tasks slower.

Open protocol

The repository documents the communication protocol and troubleshooting steps.

LIMITATIONS

Know the boundaries.

TASH is LAN tooling, not a hardened internet-facing service. Do not expose its network ports to the public internet. Local-network discovery depends on network configuration; some guest Wi-Fi networks isolate connected clients.

Android is not currently supported by the Tkinter application. A native Android Worker would be a separate implementation and is not advertised as available.
